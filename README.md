# פיקד

לוח שליטה רב-דיירי בשקעים חכמים מסוג SC1_T. האתר שולח הפעלה וכיבוי לשרת של המערכת, והשרת פונה ל-WLTE OpenAPI. מצב הממסר מתעדכן גם כשהשקע משתנה מהטלפון או מכפתור פיזי.

## הרצה

```bash
npm install
npm test
npm run dev
```

הלוח נפתח בכתובת [http://127.0.0.1:38471](http://127.0.0.1:38471).

בלי `WLTE_CLIENT_ID` ו-`WLTE_CLIENT_SECRET` המערכת עולה במצב הדגמה: אסימון, פקודות וממסרים מדומים בתוך התהליך. עם שני המפתחות המצב עובר אוטומטית ל-API החי ב-`https://openapi.svnwi.com`.

חשבונות ההדגמה:

| מי | משתמש | סיסמה |
| --- | --- | --- |
| מנהל | `admin` | `pikud-admin` |
| ישיבת הדגמה | `yeshiva` | `yeshiva-1` |
| בית כנסת הדגמה | `shul` | `shul-2` |

לקוח רואה רק את השקעים שמשויכים אליו. המנהל רואה את כולם, משייך שקעים, ופותח משתמשים.

## משתני סביבה

העתיקו את `.env.example` ל-`.env.local`.

| משתנה | משמעות |
| --- | --- |
| `WLTE_CLIENT_ID` / `WLTE_CLIENT_SECRET` | מפתחות שרת בלבד. לא נשלחים לדפדפן. |
| `WLTE_MODE` | `auto` (ברירת מחדל), `mock`, או `live`. |
| `WLTE_RELAY_STYLE` | `indexed` פונה ל-`/relays/1/commands` עם `{ "action": "ON" }`. `batch` פונה ל-`/relays/commands` עם מערך `relays`. |
| `WLTE_BASE_URL` | ברירת מחדל `https://openapi.svnwi.com`. |
| `IVR_TOKEN` | סוד שמופיע בכתובת השלוחה של ימות המשיח. |
| `SUPABASE_URL` | כתובת הפרויקט. בלי הכתובת ובלי המפתח, הנתונים נשארים ב-SQLite מקומי. |
| `SUPABASE_SERVICE_ROLE_KEY` | מפתח `service_role` מהגדרות ה-API. לא מפתח `anon`, ולא נשלח לדפדפן. |

האסימון תקף שעה. השרת מנפיק אסימון חדש אחרי 50 דקות, וגם אחרי `401`. כל פקודת ממסר מקבלת `Idempotency-Key` חדש מסוג UUID v4. אם התשובה אבדה, אותו מפתח נשלח שוב.

במצב חי השרת פותח WebSocket מול `/wlte/v1/ws` עם כרטיס חד-פעמי, מאזין ל-`device.state.changed`, ומזרים את השינוי לדפדפן. אחרי ניתוק הוא קורא מחדש את מצב השקעים הרשומים.

ההרשאות הנדרשות אצל WLTE: `device:read`, `device:control`, `device:manage`, `device:config`. אם אחת חסרה, הלוח מציג אזהרה.

## ימות המשיח

שלוחה ראשית אחת. את ארבע השורות מעתיקים מניהול → חיבור וטלפון:

```
type=api
api_link=https://האתר/api/ivr/menu
api_url_post=yes
api_add_0=token=הערך-של-IVR_TOKEN
```

`api_link` הוא כתובת האתר בלי סימן שאלה. `api_add_0` שולח את הערך של `IVR_TOKEN` בכל פנייה. `ApiPhone`, מספר המתקשר, מצורף אוטומטית.

השיחה מזהה את המתקשר לפי `ApiPhone` מול הטלפון של הלקוח, ומקריאה רק את השקעים שלו («למזגן הקש אחד»). אחרי בחירת שקע, אם הוא כבוי נאמר «להפעלה הקש אחד», ואם הוא פועל «לכיבוי הקש שתיים». הקשה 3 קובעת טיימר: ההתקן מופעל עכשיו ונכבה אחרי מספר הדקות שמוקש. הקשה 4 קובעת שעון להפעלה מאוחרת בארבע ספרות, למשל `1830`.

נשארו גם כתובות ישירות להפעלה, כיבוי ומצב של שקע אחד.

לבדיקה מהדפדפן או מ-curl הוסיפו `format=json`.

## סופרבייס

לקוחות, משתמשים, שקעים, סשנים ויומן נשמרים בסופרבייס כששני משתני הסביבה מוגדרים. בליהם הרצה מקומית נשארת על `.data/pikud.sqlite`.

1. צרו פרויקט בסופרבייס.
2. ב-SQL Editor הדביקו את `supabase/schema.sql` והריצו.
3. מ-Project Settings → API העתיקו את Project URL ואת המפתח `service_role`.
4. ברנדר, תחת Environment, הוסיפו `SUPABASE_URL` ו-`SUPABASE_SERVICE_ROLE_KEY`, ושמרו. זה מפעיל דיפלוי.

בעלייה הראשונה, אם קובץ `.data/pikud.sqlite` עדיין על השרת והטבלאות ריקות, המשתמשים והשקעים מועתקים פעם אחת. בלי הקובץ נוצר רק `admin` / `pikud-admin`, וצריך לשייך שוב את השקעים. אחרי העלייה, בניהול → חיבור וטלפון, שורת האחסון צריכה להיות «סופרבייס».

## הרצה כשרת

האסימון וחיבור ה-WebSocket חיים בתוך תהליך Node אחד. זו לא אפליקציה שמתאימה לפונקציות קצרות חיים. הריצו `npm run build` ואז `npm start` על שרת שנשאר דלוק. כשהשרת מגדיר `PORT` (רנדר מזריק אותו, למשל 10000) התהליך מאזין לפורט הזה. בלי המשתנה הוא מאזין על 38471.
